Dalibore, tohle je **velký úkol**, ale přesně ten typ práce, kde mixinová architektura začne opravdu zářit.  
Níže dostaneš **kompletní, promyšlený, vyvážený návrh**, který:

- rozděluje všechny dundery do **logických mixinových celků**,  
- každý celek je **uživatelsky přívětivý** (málo mixinů, ale ne příliš velké),  
- každý mixin je **koherentní** (všechny metody spolu dávají smysl),  
- nic není přehnaně atomické ani přehnaně monolitické,  
- je to připravené pro **mix‑and‑match** filozofii Simple systému.

A hlavně:

> **Každý mixin je přesně tak velký, aby byl užitečný, ale ne obtěžující.**

# ⭐ FINÁLNÍ NÁVRH MIXINOVÝCH SKUPIN PRO DUNDERY  
*(toto je architektura, kterou bych doporučil i do produkční knihovny)*

Níže máš **10 mixinů**, které pokrývají všechny dundery, které dávají smysl pro Simple systém.

---

# 1) 🟦 **RepresentationMixin**  
*(popis objektu, reprezentace, stringy)*

Obsahuje:

- **Repr** → `__repr__`
- **Str** → `__str__`
- **Format** → `__format__`
- **Bytes** → `__bytes__`
- **Bool** → `__bool__`

Proč spolu:  
→ Všechny určují, *jak se objekt prezentuje navenek*.

---

# 2) 🟩 **EqualityMixin**  
*(rovnost a identita)*

Obsahuje:

- **Eq** → `__eq__`
- **Hash** → `__hash__`

Proč spolu:  
→ `__eq__` a `__hash__` musí být vždy v páru.

---

# 3) 🟧 **OrderingMixin**  
*(porovnávání velikosti)*

Obsahuje:

- **Lt** → `__lt__`
- **Le** → `__le__`
- **Gt** → `__gt__`
- **Ge** → `__ge__`
- **LtLeGtGe** → fallback generátor všech čtyř

Proč spolu:  
→ Uživatel chce buď *všechno*, nebo *nic*.

---

# 4) 🟨 **NumericArithmeticMixin**  
*(aritmetika pro atomy)*

Obsahuje:

- **Add** → `__add__`
- **Sub** → `__sub__`
- **Mul** → `__mul__`
- **Div** → `__truediv__`
- **Floordiv** → `__floordiv__`
- **Mod** → `__mod__`
- **Pow** → `__pow__`

Proč spolu:  
→ Aritmetika je jeden logický celek.

---

# 5) 🟨 **NumericInplaceMixin**  
*(in‑place aritmetika)*

Obsahuje:

- **Iadd** → `__iadd__`
- **Isub** → `__isub__`
- **Imul** → `__imul__`
- **Idiv** → `__itruediv__`
- **Ifloordiv** → `__ifloordiv__`
- **Imod** → `__imod__`
- **Ipow** → `__ipow__`

Proč odděleně:  
→ Ne každý chce podporovat in‑place operace.

---

# 6) 🟨 **NumericUnaryMixin**  
*(unární operátory)*

Obsahuje:

- **Neg** → `__neg__`
- **Pos** → `__pos__`
- **Abs** → `__abs__`

Proč odděleně:  
→ Unární operace jsou často potřeba i bez aritmetiky.

---

# 7) 🟨 **NumericConversionMixin**  
*(konverze na čísla)*

Obsahuje:

- **Int** → `__int__`
- **Float** → `__float__`
- **Complex** → `__complex__`
- **Index** → `__index__`
- **Round** → `__round__`
- **Floor** → `__floor__`
- **Ceil** → `__ceil__`
- **Trunc** → `__trunc__`

Proč spolu:  
→ Všechny řeší *převod hodnoty*.

---

# 8) 🟪 **BitwiseMixin**  
*(bitové operace)*

Obsahuje:

- **And** → `__and__`
- **Or** → `__or__`
- **Xor** → `__xor__`
- **Lshift** → `__lshift__`
- **Rshift** → `__rshift__`
- **Invert** → `__invert__`

Proč spolu:  
→ Bitové operace jsou samostatná matematická oblast.

---

# 9) 🟫 **CollectionMixin**  
*(kolekční chování)*

Obsahuje:

- **Len** → `__len__`
- **Contains** → `__contains__`
- **Iter** → `__iter__`
- **Reversed** → `__reversed__`
- **Getitem** → `__getitem__`
- **Setitem** → `__setitem__`
- **Keys** → `keys()`
- **Values** → `values()`
- **Items** → `items()`
- **Dir** → `__dir__`

Proč spolu:  
→ Všechny dělají z objektu „kolekci“.

---

# 10) 🟫 **LifecycleMixin**  
*(životní cyklus objektu)*

Obsahuje:

- **Copy** → `__copy__`
- **Deepcopy** → `__deepcopy__`
- **Getstate** → `__getstate__`
- **Setstate** → `__setstate__`
- **Reduce** → `__reduce__`
- **ClassGetitem** → `__class_getitem__`

Proč spolu:  
→ Všechny řeší *životní cyklus objektu* (kopie, serializace, pickling, generika).

---

# 11) 🟦 **ContextManagerMixin**  
*(protokol with)*

Obsahuje:

- **Enter** → `__enter__`
- **Exit** → `__exit__`

Proč samostatně:  
→ Kontextový manažer je velmi specifická vlastnost.
