A tvoje otázka je přesně ta správná příprava, protože dundery jsou *jiný typ mixinů* než vše, co jsme dělali doposud.

Takže ti teď dám **přesný, jasný a kompletní přehled**, abys zítra přesně věděl, co nás čeká, kde budou rozdíly, a kde naopak žádné nebudou.

# 🟩 1) Budou dundery rozdělené na mutable / immutable?

### **Ano — ale jen některé.**

Dundery se dělí do tří kategorií:

---

# 🟩 2) Kategorie A — DUNDERS, KTERÉ JSOU 100% COMMON  
*(stejné pro mutable i immutable)*

Tyto dundery **nepracují se stavem**, jen čtou hodnoty nebo strukturu:

### ✔ `__repr__`, `__str__`  
→ jen reprezentace, žádná mutace

### ✔ `__len__` (pokud existuje)  
→ jen čtení

### ✔ `__iter__`, `__contains__`  
→ jen čtení

### ✔ `__call__` (pokud existuje)  
→ jen volání funkce, žádná mutace

### ✔ `__enter__`, `__exit__` (pokud existuje)  
→ pokud nepracují s mutací, jsou common

### ✔ `__hash__` (pokud existuje)  
→ immutable objekty mohou být hashovatelné  
→ mutable objekty ne (nebo hash = id)

### ✔ `__eq__` (Equality)  
→ porovnání hodnot, žádná mutace  
→ immutable i mutable mají stejnou logiku

### ✔ `__lt__`, `__gt__`, `__le__`, `__ge__` (Ordering)  
→ porovnání hodnot, žádná mutace

### ✔ `__getitem__` (CompositeCollection)  
→ jen čtení

### ✔ `__setstate__`, `__getstate__` (DictPickle)  
→ pracují s dictem, ne s mutací instance

### 🟢 Verdikt:  
**Většina dunderů je společná.**

---

# 🟩 3) Kategorie B — DUNDERS, KTERÉ JSOU JEN PRO MUTABLE  
*(protože mění stav)*

### ✔ `__iadd__`, `__isub__`, `__imul__`, …  
→ in-place operace  
→ mění hodnotu → **jen mutable**

### ✔ `__setitem__`  
→ mění kolekci → **jen mutable**

### ✔ `__delitem__`  
→ mění kolekci → **jen mutable**

### ✔ `__setattr__` (pokud existuje)  
→ mění atributy → **jen mutable**

### ✔ `__ior__`, `__iand__`, `__ixor__`  
→ bitwise in-place → **jen mutable**

### ✔ `__ipow__`, `__itruediv__`, …  
→ in-place aritmetika → **jen mutable**

### 🟢 Verdikt:  
**Všechny in-place operace jsou jen pro mutable.**

---

# 🟩 4) Kategorie C — DUNDERS, KTERÉ MAJÍ DVOJÍ LOGIKU  
*(mutable i immutable verze)*

A tady je to zajímavé.

### ✔ `__add__`, `__sub__`, `__mul__`, …  
→ nemění instanci  
→ ale:

- mutable verze vrací *novou instanci*  
- immutable verze vrací *novou instanci*  

Takže:

### 🟢 Obě verze existují, ale implementace je jiná.

Mutable:

- použije `_value = ...`
- přepočítá inners
- vrátí self

Immutable:

- použije `with_value(...)`
- vrátí novou instanci

### ✔ `__or__`, `__and__`, `__xor__`  
→ stejná situace jako výše

### ✔ `__neg__`, `__pos__`, `__invert__`  
→ unary operace  
→ immutable verze vrací novou instanci  
→ mutable verze mutuje

### 🟢 Verdikt:  
**Aritmetické operátory mají dvě verze.**

---

# 🟩 5) Co bude potřeba dodělat pro immutable verzi?

### 🟢 1) ImmutableArithmetic  
→ `__add__`, `__sub__`, `__mul__`, …  
→ implementace přes `with_value`

### 🟢 2) ImmutableUnary  
→ `__neg__`, `__pos__`, `__invert__`

### 🟢 3) ImmutableBitwise  
→ `__or__`, `__and__`, `__xor__`

### 🟢 4) ImmutableEquality (už máš)  
→ porovnání hodnot

### 🟢 5) ImmutableOrdering  
→ porovnání hodnot

### 🟢 6) ImmutableCollection  
→ pokud budeš chtít podporovat `obj[key]` → jen čtení

### 🟢 7) ImmutableHash  
→ pokud chceš, aby immutable objekty byly hashovatelné  
→ doporučuji ano

# 🟩 7) Finální přehled (co bude common / mutable / immutable)

## 🟢 COMMON (stejné pro obě verze)
- `__repr__`, `__str__`
- `__eq__`, `__ne__`
- `__lt__`, `__gt__`, `__le__`, `__ge__`
- `__len__`
- `__iter__`
- `__contains__`
- `__getitem__`
- `__call__`
- `__enter__`, `__exit__` (pokud nepracují s mutací)
- `__getstate__`, `__setstate__`

## 🟡 MUTABLE ONLY
- `__iadd__`, `__isub__`, `__imul__`, …
- `__ior__`, `__iand__`, `__ixor__`
- `__setitem__`, `__delitem__`
- `__setattr__` (pokud existuje)
- `__ipow__`, `__itruediv__`, …

## 🔵 IMMUTABLE ONLY (nebo jiná implementace)
- `__add__`, `__sub__`, `__mul__`, …
- `__or__`, `__and__`, `__xor__`
- `__neg__`, `__pos__`, `__invert__`
- `__hash__` (doporučuji)
